# LoRA: Low-Rank Adaptation of Large Language Models

## Introduction

**LoRA: Low-Rank Adaptation of Large Language Models** is the 2021 paper that became one of backbones of Parameter Efficient Fine-Tuning: LoRA technique. The authors proposed Low-Rank Adaptation "which freezes the pretrained model weights and injects trainable rank decomposition matrices into each layer of the Transformer architecture" - this approach is efficient since you no longer would need to train full matrix of parameters, only some part would be enough (number of parameters 10,000 times smaller) to teach model do new things.

## Background
It is common to train one large-scale model and then retrain it (fine-tune) for specific task, the problem is - number of parameters stays the same, this creates a problem that you need to do a lot of computation to update the weights and latency also increases. Inspired by another research, authors hypothesized that the change in weights during model adaptation has a low rank leading to LoRA approach. "LoRA allows us to train some dense layers in a neural network indirectly by optimizing rank decomposition matrices of the dense layers’ change during adaptation instead, while keeping the pre-trained weights frozen".
> LoRA possesses several key advantages.
> - A pre-trained model can be shared and used to build many small LoRA modules for different tasks. We can freeze the shared model and efficiently switch tasks by replacing the
matrices, reducing the storage requirement and task-switching overhead significantly.
> - LoRA makes training more efficient and lowers the hardware barrier to entry by up to 3
times when using adaptive optimizers since we do not need to calculate the gradients or
maintain the optimizer states for most parameters. Instead, we only optimize the injected, much smaller low-rank matrices.
> - Our simple linear design allows us to merge the trainable matrices with the frozen weights
when deployed, introducing no inference latency compared to a fully fine-tuned model, by
construction.
> - LoRA is orthogonal to many prior methods and can be combined with many of them, such
as prefix-tuning

## Architecture
### $W_0 + BA$ trick
In a standard fine-tuning scenario, you would change the values inside the original weight matrix ($W_0$). Instead, LoRA freezes ($W_0$) and represents the change ($\Delta W$) as the product of two much smaller matrices, A and B.
- $W_0$ has the "knowledge" the model already has.
- $BA$: The "tuning" or "new task knowledge."
- The Rank ($r$): decomposes the new matrix parameters and displays how many parameters should stay learnable.<br>
  (If your original matrix is $1000 \times 1000$ (1,000,000 parameters), and you pick a rank $r=8$, then matrix A is $8 \times 1000$Matrix B is $1000 \times 8$ and total parameters: $8,000 + 8,000 = 16,000$)

The Forward Pass: $h = W_0x + BAx$This explains how the model actually runs during training. When an input ($x$) comes in, it flows through two paths simultaneously:The Frozen Path: It multiplies with the original weights ($W_0x$).The Trainable Path: It multiplies with $A$, then $B$ ($BAx$).The results are added together. Because matrix multiplication is distributive, $W_0x + BAx$ is mathematically equivalent to $(W_0 + BA)x$. This means after training, you can actually merge $BA$ back into $W_0$ for inference, resulting in zero latency overhead.

### The Forward Pass
When an input ($x$) comes in, it flows through two paths simultaneously: 
- The Frozen Path: It multiplies with the original weights ($W_0x$).
- The Trainable Path: It multiplies with $A$, then $B$ ($BAx$).

The results are added together. Because matrix multiplication is distributive, $W_0x + BAx$ is mathematically equivalent to $(W_0 + BA)x$. This means after training, you can actually merge $BA$ back into $W_0$ for inference, resulting in zero latency overhead.

### Weight Merging
During training, we keep $W_0$ and $BA$ separate. But once training is done, we have two matrices that are the same shape (both are $d \times k$).Because of the rules of matrix addition, we can simply add them together once and save the result as a new single matrix ($W$). <br>
**The switch**: you can easily subtract LoRA weights and add another LoRA weights to improve performance on specific task

## Limitations

- The Batching Dilemma: If you "merge" the weights to eliminate latency, you can only serve one task per batch.
- Dynamic Complexity: If you want to process a single batch where different inputs use different LoRAs (e.g., User A needs French, User B needs Coding), you cannot use the merged weights. You would have to keep the weights separate, which re-introduces some latency.
